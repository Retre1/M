## Что изменилось против первой редакции

Первая редакция ставила фазу 2 как «доказать или опровергнуть edge». Замер
показал, что это **невозможно в текущем виде**, и не из-за качества политики:

```
max_value = 100 000 × 0.10             = 10 000
raw_value = confidence × 0.25 × 10 000 = 2 500 × confidence
lots      = 2 500 / (1.08 × 100 000)   = 0.023   при confidence = 1.0
```

Максимальная позиция — 0.023 лота; при `|action| < 0.43` округление до шага
лота даёт ноль. Фактический замер на бэктесте: **671 отказ из 1155 решений** с
причиной «Position size computed to zero», прошедшие сделки — минимальным
лотом, средняя экспозиция **0.045 % капитала**.

Это та же форма, что обесценила Run 5 ($50 нотионала на $100k, итог −$4.77 —
статистически неотличимо от нуля). Поэтому сайзинг повышен из подпункта 2.4 в
**ворота, без которых фаза 2 не имеет смысла**.

## Ворота 2A — экспозиция (✅ пройдены 2026-08-17)

**Решение владельца: вариант B**, ATR-сайзинг от риска на сделку. Реализовано
в `PositionSizer`: размер выводится из расстояния до стопа при лимите риска
`risk_per_trade_pct` (по умолчанию 1 %, в production 0,5 %), сверху потолок по
плечу `max_leverage`. Параметры проведены через `PositionSizingConfig` и YAML.

**Критерий прохождения:** средняя экспозиция ≥ 0.5 % капитала и доля отказов
«Position size computed to zero» < 5 % решений.

**Замер после правки** (бэктест с включённым риск-менеджером): средняя
экспозиция **2,138 %** против 0,045 % до, отказов по нулевому размеру — ноль.
Оба порога пройдены, `exposure_is_meaningful` больше не гасит вердикт.

**Осталось как отдельное решение:** `forex_env.py:731` считает размер сам, в
шкале условного объёма и мимо `PositionSizer`, — обучение и оценка идут при
разных схемах сайзинга. Правка меняет масштаб наград и делает прогоны 1–6
несопоставимыми с последующими.

**Ворота 2 (решающие) — переформулированы 18.08 после ревью.**

Прежняя формулировка («80 % окон», «медианный PF > 1.1») сжимала фолд до одного
бита и опиралась на PF, у которого нет выборочного распределения. Действующие
условия:

1. **Мощность.** В фолде не менее **30 сделок**, иначе фолд исключается из
   вердикта и перечисляется в отчёте. Ни один фолд не прошёл порог → вывод
   «свидетельств нет», а не «преимущества нет».
2. **Экспектация.** Односторонний t-тест среднего **R** против нуля, p < 0.05.
   R = P&L / риск на входе, из первоначального (не трейлингового) стопа.
3. **Устойчивость.** Победа над лучшим baseline по фолдам, **точный биномиальный
   тест**, p < 0.05. При 9 фолдах это 8 побед из 9 (88,9 %), а не 80 %:
   P(X≥8) = 0.0195, P(X≥7) = 0.0898.
4. **Оговорка.** Фолды — смежные куски одного ряда, биномиальный p оптимистичен;
   печатается в отчёте вместе с числом.

Оба барьера обязательны: значимое среднее R при проигрыше baseline на
большинстве сегментов — не преимущество, как и победа по сегментам при нулевой
экспектации.

**Критерий отказа:** после Run 7–8 медианный OOS PF < 1.0 → фаза 3, а не
подкрутка гиперпараметров. Текущая база: 0.957 и 0.736 — обе ниже единицы.

## Фаза 3 — упрощение (если ворота 2 не пройдены)

Сейчас одновременно работают TFT + HiveMind + World Model + PER + EWC +
adversarial + curriculum, и ни один компонент не имеет доказанного вклада в
ΔSharpe. При отрицательном итоге нельзя сказать, что именно мешает.

1. Отключить HiveMind → один TQC-агент.
2. Отключить World Model и фундаментальные признаки.
3. Оставить: цена, ATR, режим, структура.
4. Reward: только `LogReturnReward`.
5. Если упрощённая версия даёт положительный OOS Sharpe — возвращать
   компоненты **по одному**, фиксируя ΔSharpe и ΔMaxDD каждого.

**Критерий отказа проекта в текущей постановке:** если и упрощённая модель не
бьёт baseline — на EURUSD в этом окне edge ≥ издержек нет. Менять постановку
(мультисимвольный портфель, другой таймфрейм, другие признаки), а не углублять
текущую конфигурацию.
